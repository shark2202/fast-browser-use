# Goal: Optional ego-browser Backend with Group Isolation & Human–AI Collaboration

Status: Proposed · Date: 2026-09-25 · Realized by: `docs/ego-backend-design.md` · Project: fast-browser-use

## 1. Problem

`fbu` drives an **isolated, empty-profile Playwright Chromium**. This is correct for headless benchmarks and CI, but it cannot reach the user's **real logged-in sessions**. Tasks that require authentication on sites the user already uses (Google, GitHub, internal systems, paywalled content, 2FA-gated flows) are unreachable without the user manually recreating login state inside the isolated browser — which defeats the purpose.

There is also no notion of **isolation between concurrent task groups**: one `fbu` run's browser state is not separable from another's, and there is no way for a human to step into a stuck loop (login wall, captcha, ambiguous approval) and have the agent continue cleanly from the human's action.

## 2. Objective

Add **ego-browser** as an **optional, opt-in** browser backend that:

1. **Reuses the user's real logged-in browser state** (ego lite's profiles/sessions), so authenticated tasks work without manual re-login.
2. **Isolates work by group** — parallel teams/tasks get independent browser instances and (optionally) independent cookie jars, with no cross-contamination.
3. **Supports human–AI collaboration** — the agent can hand control to a human at a blocking step, exit cleanly, and **resume** from where the human left off, across separate CLI invocations.

Playwright stays the default backend; the ego backend is selected only when its capabilities are needed.

## 3. Success Criteria

A goal is met only when **all** hold, verified by evidence (tests + telemetry):

1. `FBU_BROWSER=playwright` (default) — zero behavioral regression vs the current `main` branch: existing `test_*`, `fbu record`, and the Qwen3.5-9B Wikipedia demo trace remain byte-for-byte equivalent in page-dict shape and pass/fail status.
2. `FBU_BROWSER=ego --group g1` runs a non-authenticated task (e.g., Wikipedia search) end-to-end on `example.com`/`wikipedia.org` via the ego lite app, producing the **same page-dict contract** as Playwright (keys: `url/text/actions/scroll/marker/page_key/guards/fingerprint/screenshot/ready`). The agent loop, `snapshot.js`, guards, and `verification.py` run **unchanged**.
3. **Group isolation**: two concurrent `fbu` runs under `--group g1` and `--group g2` operate in **separate** ego browser services; neither observes the other's tabs/pages/cookie state. Same group across runs **reuses** the persisted space (`spaceId`).
4. **Human–AI handoff**: a run blocked by a login wall (fixture or live) reaches `status=handoff`, calls `task.handOff()`, keeps the space, and exits with a resume instruction. After the human completes the step in ego lite, `fbu resume <spaceId>` calls `takeOverTaskSpace`, continues from the human's page, and completes the task. The model **never** selects the handoff (zero-hallucination principle preserved).
5. **Latency is documented, not regressed silently**: ego backend measured ~2–3 s/step (vs Playwright ~0.5 s); the per-step two-invocation batching is the minimum feasible given the blocked stdin protocol, and the number is recorded in the SKILL/docs.
6. **Zero new dependencies** for the default (Playwright) path; the ego path requires only the external `ego-browser` CLI on PATH (`pyproject.toml` unchanged).
7. **Platform scope is honest**: the ego backend is macOS-only (ego lite is a desktop app); Linux/Windows/headless remain Playwright-only. The CLI preflight rejects ego on unsupported setups with an actionable message.

## 4. Scope

**In scope**
- `Browser` protocol abstraction; rename current `browser.py` → `PlaywrightBrowser`; new `EgoBrowser`.
- Group isolation via `--ego-server-name=fbu-<group>` (primary) + optional `FBU_EGO_PROFILE` (secondary).
- Resumable session: `spaceId` persisted in trace; `fbu resume <spaceId>` + `fbu run --resume` alias.
- Harness-driven handoff (heuristic detector + `BLOCKED` status), gated by `FBU_EGO_HANDOFF=auto|never|always`.
- CLI: `--browser`, `--group`, `--profile`, `--handoff`, `resume` subcommand, ego preflight.
- Tests: unit (templates, detector, mapping, trace round-trip) + gated live integration (`FBU_EGO_LIVE=1`).
- Docs/SKILL: a short "Optional ego backend" section with caveats.

**Out of scope (non-goals)**
- Replacing Playwright as default/only backend.
- Sub-second per-step latency on ego (accepted cost; no undocumented direct-IPC shortcut).
- Linux/Windows/headless support for the ego backend.
- Model-driven handoff (rejected — breaks zero-hallucination).
- Programmatic profile creation (ego lite app UI only; `FBU_EGO_PROFILE` references existing ids).
- OpenWiki page edits (regenerated by the scheduled workflow; only source docs change).

## 5. Key Constraints

- **Zero-hallucination preserved**: the model continues to choose only among observed DOM elements; handoff is harness-triggered, never model-generated.
- **Guarded execution preserved**: `StalePage`, freshness guards, DONE-as-gate, and independent `verification.py` checks run identically on both backends.
- **Local-first preserved**: no cloud inference introduced; ego only changes the browser driver, not the model path.
- **No black-box IPC**: do not reverse-engineer ego lite's named-service socket; drive only via the documented `ego-browser nodejs` CLI + `page.cdp()`/`page.evaluate()` escape hatches.

## 6. Stakeholders & Usage

- **End user (macOS, ego lite installed)**: runs authenticated browser tasks locally; collaborates with the agent via handoff→resume.
- **Team lead**: runs parallel isolated task groups per team via `--group`.
- **fbu maintainer**: keeps Playwright as the benchmark/CI default; treats ego as a capability backend, not a performance path.

## 7. Measurable Outcome

A single authenticated task (e.g., "save a setting on a site the user is logged into") completes via `fbu run --browser ego --group personal` + one `fbu resume`, with the human performing only the login step, and the agent performing all navigation/form/verification — something impossible on the Playwright backend today. Telemetry trace records `ego.space_id`, `group`, `handoffs[]`, and per-step latencies.
